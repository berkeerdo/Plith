# Notch Widget Carousel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The open notch becomes a fixed frame with paged widgets — clock, weather, media, audio — reached by a horizontal swipe, a tilt wheel, `Shift`+wheel or a click on the page dots. An event (a volume key, a track change) stops opening that frame and gets its own short HUD shape instead.

**Architecture:** A pure `NotchPager` owns the page index and the wheel-delta accumulator; nothing about it touches WPF. `OsdContent` gains a fixed-size widget frame with a `*` page row over a fixed 14 DIP dots lane. `WM_MOUSEHWHEEL` is taken in the `HwndSource` hook — WPF has no event for it — decoded into a delta and handed to the pager. Each widget is a `UserControl` selected by the frame, not an `ICard`: cards are the OSD's event surface and stay that way.

**Tech Stack:** WPF + .NET 10 (`net10.0-windows10.0.22000.0`), x64, xunit. `HwndSource.AddHook` for `WM_MOUSEHWHEEL` / `WM_MOUSEWHEEL`, `DoubleAnimation` for the slide and the marquee, `DispatcherTimer` for the sky loop.

**Spec:** `docs/superpowers/specs/2026-09-07-notch-widget-carousel.md` — read it before Task 1, including the 2026-09-10 revisions. It records *why* the frame is fixed, why the transport is on the right, why the dots lane is a fixed row, and what the bezel must not follow. This plan does not repeat that reasoning.

**Mockup:** `docs/superpowers/design/notch-design.html`. Every state, timing and dimension below is measurable in it. Open it before starting a task whose numbers you are about to type.

## Task 1 — `NotchPager`, pure

**Read first:** spec §5. Wheel deltas are not page counts.

- [ ] Write `tests/Plith.Tests/NotchPagerTests.cs` first. Cases: one large delta commits exactly one page; a stream of small deltas summing past the threshold commits **one** page, not several; after a commit no further page is committed until the accumulator falls back below the rearm floor; direction is respected; the index wraps in both directions; a page count of 1 never moves.
- [ ] Implement `NotchPager` with `PageCount`, `Index`, `Accumulate(int delta) -> bool committed`, `Commit(int direction)`, `Reset()`.
- [ ] Threshold `120` (one `WHEEL_DELTA`), rearm floor `40`. Both named constants with a comment saying they are provisional until measured on the user's touchpad.
- [ ] `dotnet test` — expect 221 + new.
- [ ] Commit: `feat(notch): add a pure pager for widget paging`

## Task 2 — `WM_MOUSEHWHEEL` reaches the pager

**Read first:** spec §5. WPF has no event for this message; it must come out of the hook.

- [ ] In `BandWindow.SourceHook`, decode `WM_MOUSEHWHEEL` (0x020E) and `WM_MOUSEWHEEL` (0x020A) with `MK_SHIFT`, and raise a `HorizontalWheel` event carrying a signed delta. Sign convention documented in a comment: `WM_MOUSEHWHEEL` is positive-right, `WM_MOUSEWHEEL` is positive-up, so the shift path is negated.
- [ ] `OsdHost` subscribes, feeds `NotchPager.Accumulate`, and calls the frame's page change on a commit. Ignore entirely when the presentation is not `AmbientNotchPresentation`, or when the notch is not open.
- [ ] Add a `_log?.Info` on each commit with the delta and the new index — this is the only way the touchpad's real behaviour can be read back later, and spec §6 requires instrumenting from inside rather than sampling from outside.
- [ ] Build, test, lint.
- [ ] Commit: `feat(notch): route horizontal wheel messages to the pager`

## Task 3 — The frame, the dots lane, the slide

**Read first:** spec §2 and the mockup. The lane is fixed, not `auto`.

- [ ] `NotchGeometry` gains `OpenFrameDip = new Size(356, 116)`, `DotsLaneDip = 14`, `HudDip = new Size(300, 46)`, `HudWideDip = new Size(372, 54)`.
- [ ] `WidgetFrame`: `RowDefinition Height="*"` over `Height="14"`, `ClipToBounds="True"` on the page row. Dots are `ToggleButton`s in an `ItemsControl` with an accessible name each (`Page 2 of 5`) — a bare `Border` cannot surface one, which is the defect the lint exists to catch.
- [ ] Slide transition: the incoming page animates `TranslateTransform.X` from ±14 and opacity 0→1 over 260 ms, `CubicEase` out. The outgoing page is removed **on the animation's completion or on the next page change, whichever comes first** — do not rely on `Completed` alone, per spec §7.
- [ ] Clicking a dot pages directly; the hit target is padded to ≥ 20 DIP even though the dot is 5.
- [ ] Build, test, lint. No new unit tests — this is all `UserControl`, which the suite cannot construct.
- [ ] Commit: `feat(notch): add the fixed widget frame with a page-dot lane`

## The defect class this plan must not repeat

Every defect on this branch shares one shape: **state derived from a single moment, or a single callback, that turned out not to fire.** `BeginAnimation(prop, null)` removes a clock without raising `Completed` — five times. One synchronous `Measure` read a tree the `ItemsControl` had not materialised. A parked flag written in a completion handler left a closed notch believing it was open.

Three values in this slice are in exactly that hazard: **the page index**, **the slide's in-flight state**, and **the marquee's overflow measurement**. Each must be recomputed where it is used, or owned by a pure object with no completion callbacks at all. That is why Tasks 1 and 5 begin with a pure type and a test file rather than a control.
