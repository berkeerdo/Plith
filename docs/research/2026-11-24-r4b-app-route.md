## 3. Per-app routing: IAudioPolicyConfigFactory (source: EarTrumpet, read via `gh api repos/File-New-Project/EarTrumpet/contents/...`, branch master)

URLs (github.com/File-New-Project/EarTrumpet/blob/master/):
- `EarTrumpet/Interop/MMDeviceAPI/IAudioPolicyConfigFactoryVariantFor21H2.cs`
- `EarTrumpet/Interop/MMDeviceAPI/IAudioPolicyConfigFactoryVariantForDownlevel.cs`
- `EarTrumpet/Interop/Helpers/AudioPolicyConfigFactory.cs`, `...ImplFor21H2.cs`, `...ImplForDownlevel.cs`
- `EarTrumpet/DataModel/WindowsAudio/Internal/AudioPolicyConfigService.cs`
- `EarTrumpet/Extensions/OperatingSystemExtensions.cs`

Facts (verified from that source):
- Choice by build: `Environment.OSVersion.Build >= 21390` (`Version21H2 = 21390`) -> 21H2 variant, else downlevel. Build 26300 takes the 21H2 variant.
- IIDs: **21H2 and later `ab3d4648-e242-459f-b02f-541c70306324`**; downlevel (Win10 up to 21H1 era) `2a59116d-6c4f-45e0-a74f-707e3fef9258`. Both are `InterfaceIsIInspectable`.
- Activation: `RoGetActivationFactory("Windows.Media.Internal.AudioPolicyConfig", iid, out factory)` (class name is an HSTRING; combase). Factory is an activation factory, not a CoCreateInstance object.
- Vtable: IUnknown (3) + IInspectable (GetIids, GetRuntimeClassName, GetTrustLevel = 3) then 19 incomplete slots in this order: add_CtxVolumeChange, remove_CtxVolumeChanged, add_RingerVibrateStateChanged, remove_RingerVibrateStateChange, SetVolumeGroupGainForId, GetVolumeGroupGainForId, GetActiveVolumeGroupForEndpointId, GetVolumeGroupsForEndpoint, GetCurrentVolumeContext, SetVolumeGroupMuteForId, GetVolumeGroupMuteForId, SetRingerVibrateState, GetRingerVibrateState, SetPreferredChatApplication, ResetPreferredChatApplication, GetPreferredChatApplication, GetCurrentChatApplications, add_ChatContextChanged, remove_ChatContextChanged. Then slot 20 `SetPersistedDefaultAudioEndpoint(uint processId, EDataFlow flow, ERole role, HSTRING deviceId) -> HRESULT`, slot 21 `GetPersistedDefaultAudioEndpoint(uint processId, EDataFlow flow, ERole role, out HSTRING deviceId)`, slot 22 `ClearAllPersistedApplicationDefaultEndpoints()`. The two variants have identical layouts; only the IID differs. (The 19-slot count is the same trap as the 10-slot IPolicyConfig: a miscount lands on a wrong method; measure first with Get on a known pid.)
- Device id string: `\\?\SWD#MMDEVAPI#` + MMDevice endpoint id + `#{e6327cad-dcec-4949-ae8a-991e976a79d2}` for render (`#{2eef81be-33fa-4800-9670-1cd474972c3f}` for capture). The MMDevice id is the usual `{0.0.0.00000000}.{guid}` string from `IMMDevice::GetId` (the same `Endpoint.id` the workspace already holds). Passed as an HSTRING (EarTrumpet uses `WindowsCreateString`). Get returns the same wrapped form; EarTrumpet's `UnpackDeviceId` strips prefix and suffix.
- Set semantics: EarTrumpet calls Set twice, role eMultimedia then eConsole (never eCommunications). Get is called with `eMultimedia | eConsole` (= 1; it is just a role value, it works as eMultimedia). A null/empty HSTRING (EarTrumpet passes IntPtr.Zero when deviceId is blank) clears the persisted choice for that pid (= follow default). `ClearAllPersistedApplicationDefaultEndpoints` is the "Reset" button of Settings > Sound > Volume mixer.
- Granularity: keyed by process id in the call, but Windows persists it per application (per exe/package); EarTrumpet's group move loops over all distinct pids of the app (`AudioDeviceSessionGroup.MoveToDevice`). Registry location of persisted values is from memory only (HKCU\Software\Microsoft\Internet Explorer\LowRegistry\Audio\PolicyConfig\PropertyStore): unverified.
- Live or restart: EarTrumpet's UI moves a currently playing app with one click, relying on the call to re-route the active stream, so the design intent is live for apps whose session exists. Unverified on build 26300; test with a running Spotify and a paused one. EarTrumpet issue #403 (https://github.com/File-New-Project/EarTrumpet/issues/403): a persisted choice pointing to an unavailable device leaves the app silent and invisible; maintainer answer: use Windows Settings > Sound > Volume mixer "Reset" (= Clear All) because "Windows has known bugs around this device redirection scenario". Design consequence: only offer reachable active endpoints, and offer "back to default" (null HSTRING) per app.
- History: GUID changed with build 21390 (Win11 pre-release); SoundDeck issue https://github.com/GeekyEggo/SoundDeck/issues/52 records the Win11 break ("unable to instantiate IAudioPolicyConfigFactory", fixed Nov 2021 by using the 21H2 IID). hoobio/earmark (github.com/hoobio/earmark) describes the same class name. I found no source for 24H2/25H2 changes; build 26300 is untested, so a probe is step 0.

## 4. SMTC session to render pids

- SMTC gives `SourceAppUserModelId` (`plith-media/src/session.rs:56-61`). Values seen: Store Spotify `SpotifyAB.SpotifyMusic_<hash>!Spotify`, desktop Spotify `Spotify.exe`, browsers `Chrome`, `msedge`, `firefox` forms or `<exe>` names; no pid is exposed.
- Enumerate `IMMDevice` for every active render endpoint (not only the default: the app may already be routed elsewhere) -> `Activate(IAudioSessionManager2)` -> `GetSessionEnumerator` -> per `IAudioSessionControl`.cast `IAudioSessionControl2`: `GetProcessId`, `IsSystemSoundsSession` (skip; pid 0), `GetGroupingParam`, `GetSessionIdentifier` (contains the exe path or for packaged apps the family name, `...|%b{guid}`), `GetState` (Active or Inactive; Expired ignore). windows-rs 0.62.2 has these: `IAudioSessionManager2::GetSessionEnumerator`, `IAudioSessionControl2::GetProcessId` in `windows-0.62.2/src/Windows/Win32/Media/Audio/mod.rs` under feature `Win32_Media_Audio` (already enabled in plith-audio). Sessions exist only while the app has opened a render stream; a paused Spotify keeps its session (state Inactive) but a closed player has none, so "no session found" is an expected, handled state, not an error.
- Robust match, in order, per candidate pid:
  1. Packaged: `GetApplicationUserModelId` on the process handle (`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`, feature `Win32_Storage_Packaging_Appx`) equals SMTC AUMID (case-insensitive). Packaged apps with the SMTC AUMID `Family!App`: compare family name segment too.
  2. Unpackaged: `QueryFullProcessImageNameW` (already used in `plith-system/src/flyout/hook/query.rs:60`) file stem equals the AUMID with `.exe` removed (ordinal ignore-case), the same normalisation as `derive::source_label`. Browsers: the SMTC id is a short name (`Chrome`, `msedge`); map by stem and known aliases.
  3. Process tree: Chromium/Electron/Spotify render audio in a child "audio service" or utility process, so the session pid is a child whose image is the same exe but not the main window process. Match by exe stem across ALL pids, then set the route for every distinct pid of that exe (what EarTrumpet does per app group). Walk parent pids (`CreateToolhelp32Snapshot`) only as fallback when the child has a different exe.
  4. Tie-break: prefer sessions with `AudioSessionStateActive`; if the match set is empty, do nothing and say so (do not guess by title).
  5. Never match by window title or display name alone.
- Because Windows persists per app, one successful Set on any matched pid covers the app after restart, but calling it for all matched pids matches EarTrumpet and covers multi-process browsers while running.

## 5. windows crate 0.62.2 (workspace `Cargo.toml:13`, checked in `~/.cargo/registry/src/*/windows-0.62.2` and context7 /microsoft/windows-rs/0.62.0)

- `RoGetActivationFactory<T: Interface>(&HSTRING) -> Result<T>` is in `windows::Win32::System::WinRT` (`Win32/System/WinRT/mod.rs:175`), feature `Win32_System_WinRT` (parent `Win32_System`). It uses `T::IID`, so define the factory with `#[windows_core::interface("ab3d4648-...")]` and call `RoGetActivationFactory::<IAudioPolicyConfigFactory>(&HSTRING::from("Windows.Media.Internal.AudioPolicyConfig"))`.
- Interface base must be IInspectable: `#[interface("...")] unsafe trait X: IInspectable` then the 19 placeholder methods then the 3 real ones. `windows_core::IInspectable` exists; the workspace already uses `windows_core::interface` with IUnknown in `policy.rs`. HSTRING is `windows::core::HSTRING` (already used in `crates/plith/src/instance.rs:5`); pass `&HSTRING` / `HSTRING::from(wrapped_id)`; Get returns an `HSTRING` out-param (use `*mut core::mem::MaybeUninit`/`HSTRING` out pointer in the hand-written signature, `HSTRING::default()` as null for clear).
- Needed Cargo features to add: `Win32_System_WinRT` (activation), `Win32_Storage_Packaging_Appx` (AUMID from process; add only if packaged matching is used), `Win32_System_Threading` (OpenProcess, QueryFullProcessImageNameW), `Win32_System_Diagnostics_ToolHelp` (parent walk, optional). `Win32_Media_Audio`, `Win32_System_Com` already present in plith-audio. COM must be initialised on the calling thread (the endpoints service thread already is; keep all calls there like the other writes).

## 6. Risks and fail-closed behaviour

- Undocumented: IID, vtable order and class name can change in any release (history: pre-21390 -> 21390, and the Win11 breakage in 2021). Failure modes: `RoGetActivationFactory` returns `E_NOINTERFACE` or `REGDB_E_CLASSNOTREG` (clean), or a wrong slot count calls the wrong method (the dangerous case: could write something else). Mitigations: (a) probe on startup/first open with `GetPersistedDefaultAudioEndpoint` on our own pid or a matched pid and require S_OK and a parsable `\\?\SWD#MMDEVAPI#...` result before enabling the picker, else the route stays read-only (today's behaviour); (b) check build number and log it with the HRESULTs; (c) every Set followed by a Get readback, report failure if it differs; (d) feature disabled for the session after one failure (no retries storming).
- Never call with arbitrary ids: only ids from the active-endpoint list, wrapped by the fixed prefix/suffix; capture flow is out of scope.
- Stale device: a persisted route to an unplugged device silences the app (EarTrumpet #403). Provide "default" (null HSTRING) as the first station; consider clearing a persisted route whose endpoint is no longer active.
- Windows Settings Volume mixer shows and can reset the same state, so the user has a recovery path outside Plith. `ClearAllPersistedApplicationDefaultEndpoints` is a global reset: do not call it from the picker.
- Voicemeeter: when VM runs, apps normally go to the VM virtual device; a per-app route to a hardware endpoint bypasses the mixer. The picker must label that (reachable stations from `Endpoint` list include Voicemeeter inputs).
- Testing constraints: Plith rules forbid running plith.exe here and moving the mouse; a probe example in `crates/plith-audio/examples/` (like `verify_writes.rs`) is the right vehicle, run via `heavy-run.mjs`. Pure parts (id wrapping/unwrapping, AUMID-to-exe matching, choice of stations) go to `plith-core`/plith-audio with unit tests.
- Design carry-over from WPF: read endpoint list once on open, no live reshuffle; focus not on a device; failure text stays visible ("Could not switch output", Turkish copy needed); current route marked; overflow when too many outputs.
